# 博客分类与标签规范

> 本文档定义了本博客的分类体系和标签使用规范，确保内容组织的一致性和可维护性。

## 📋 分类体系

### 一级分类（4 个核心分类）

| 分类     | 说明                             | 示例文章                                 |
| -------- | -------------------------------- | ---------------------------------------- |
| **教程** | 操作指南、步骤教学、配置指南     | Hugo 博客搭建、Git 配置、网络设置        |
| **笔记** | 学习总结、理论整理、论文阅读     | 联邦学习基础、PyTorch 入门、公平性定义   |
| **工具** | 软件使用技巧、配置教程、效率提升 | Cursor 使用、Markdown 语法、Windows 优化 |
| **项目** | 个人作品、开源项目、实践成果     | Stellaris DLC Helper                     |

### 分类原则

✅ **应该这样做：**

- 每个分类下应该有**多篇文章**支撑（至少 3-5 篇）
- 分类之间应该有**清晰的边界**
- 一篇文章**只属于一个分类**
- 分类命名保持**简洁**（2-4 个字）

❌ **不应该这样做：**

- 分类过细（如"博客搭建"、"Hugo 配置"）
- 一个分类只有 1-2 篇文章
- 一篇文章属于多个分类
- 分类命名过长或过于具体

## 🏷️ 标签策略

### 标签类型

| 类型         | 说明                 | 示例                                     |
| ------------ | -------------------- | ---------------------------------------- |
| **技术栈**   | 具体技术、框架、工具 | `Hugo`, `Git`, `Python`, `PyTorch`       |
| **应用场景** | 业务场景、使用场景   | `博客搭建`, `联邦学习`, `游戏联机`       |
| **具体工具** | 软件名称、平台       | `Cursor`, `CentOS`, `OpenVPN`, `VS Code` |
| **技能点**   | 具体技能、方法       | `Markdown`, `GitHub Actions`, `静态网站` |

### 标签原则

✅ **应该这样做：**

- 每篇文章 **3-8 个标签**
- 标签应该**具体且有区分度**
- 使用**一致的命名**（如 `GitHub` 不要有时写 `Github`）
- 标签可以**跨分类复用**

❌ **不应该这样做：**

- 标签与分类重复（如分类是"教程"，标签就不要写"教程"）
- 标签过于宽泛（如"技术"、"学习"）
- 一篇文章标签超过 10 个
- 生造只有自己能看懂的标签

## 📝 使用示例

### 示例 1：Hugo 教程

```yaml
categories:

tags:

  - "GitHub Pages"

  - "Git"
```

## 🎯 决策框架

当不确定如何分类时，问自己三个问题：

1. **这个分类下会有多篇文章吗？**
   - 如果只有 1-2 篇，说明分类太细了
   - 应该归入更宽泛的分类

2. **用户会通过这个分类浏览吗？**
   - 用户会点"教程"看所有教程
   - 但不会点"博客搭建"，因为标签搜索更直接

3. **这个分类跟其他分类有清晰边界吗？**
   - "教程" vs "笔记"：清晰（一个是指南，一个是总结）
   - "博客搭建" vs "Hugo 技巧"：模糊（容易重叠）

## 💡 核心洞察

> **分类是为了"浏览"，标签是为了"搜索"**

- 用户想**随便看看** → 点分类（"我想看教程"）
- 用户想**找具体内容** → 搜标签（"我想找 Hugo 相关文章"）

**记住：分类是"抽屉"，标签是"便利贴"。一个抽屉里可以有很多贴了不同便利贴的文件。**

## 📊 分类统计

定期查看各分类的文章数量，确保分布合理：

- 教程：X 篇
- 笔记：X 篇
- 工具：X 篇
- 项目：X 篇

如果某个分类文章过少（<3 篇），考虑：

1. 是否分类太细？合并到更大的分类
2. 是否这个方向写得少？正常现象
