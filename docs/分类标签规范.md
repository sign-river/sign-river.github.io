# 博客分类与标签规范

> 本文档定义了本博客的分类体系和标签使用规范，确保内容组织的一致性和可维护性。

## 📋 分类体系

### 一级分类（7 个核心分类）

| 分类     | 说明                                       | 示例文章                                          |
| -------- | ------------------------------------------ | ------------------------------------------------- |
| **开发** | 编程工具、AI 辅助、开发技巧                | Cursor 使用、Markdown 语法、GitHub 学生包         |
| **系统** | 系统优化、站点运维、Windows 技巧、软件配置、网络工具 | Hugo 站点维护、Windows 设置、网络工具、Clash Verge |
| **办公** | Word、WPS 使用技巧与问题解决               | WPS 图片模糊、LaTeX-OCR 插入公式                  |
| **游戏** | 游戏工具、游戏配置、问题排查               | 群星 DLC 解锁、游戏联机教程、游戏故障解决         |
| **笔记** | 学习总结、理论整理、论文阅读               | 联邦学习基础、PyTorch 入门、公平性定义            |
| **项目** | 个人作品、开源项目、实践成果               | Stellaris DLC Helper                              |
| **生活** | 运营商服务、消费维权、办事流程、出行与家庭日常 | 流量卡注销、余额退款、生活服务办理指南                 |

### 分类原则

✅ **应该这样做：**

- 每个分类下应该有**多篇文章**支撑（至少 3-5 篇）
- 分类之间应该有**清晰的边界**
- 一篇文章**只属于一个分类**
- 分类命名保持**简洁**（2-4 个字）

❌ **不应该这样做：**

- 分类过细（如"博客搭建"、"Hugo 配置"）
- 一个分类只有 1-2 篇文章
- 一篇文章属于多个分类
- 分类命名过长或过于具体

## 🏷️ 标签策略

### 标签类型

| 类型         | 说明                 | 示例                                     |
| ------------ | -------------------- | ---------------------------------------- |
| **技术栈**   | 具体技术、框架、工具 | `Hugo`, `Git`, `Python`, `PyTorch`       |
| **应用场景** | 业务场景、使用场景   | `博客搭建`, `联邦学习`, `游戏联机`       |
| **具体工具** | 软件名称、平台       | `Cursor`, `CentOS`, `OpenVPN`, `VS Code` |
| **技能点**   | 具体技能、方法       | `Markdown`, `GitHub Actions`, `静态网站` |

### 标签原则

✅ **应该这样做：**

- 每篇文章 **3-8 个标签**
- 标签应该**具体且有区分度**
- 使用**一致的命名**（如 `GitHub` 不要有时写 `Github`）
- 标签可以**跨分类复用**

❌ **不应该这样做：**

- 标签与分类重复（如分类是"教程"，标签就不要写"教程"）
- 标签过于宽泛（如"技术"、"学习"）
- 一篇文章标签超过 10 个
- 生造只有自己能看懂的标签

## 🎯 决策框架

当不确定如何分类时，问自己三个问题：

1. **这个分类下会有多篇文章吗？**
   - 如果只有 1-2 篇，说明分类太细了
   - 应该归入更宽泛的分类

2. **用户会通过这个分类浏览吗？**
   - 用户会点"系统"看站点维护、系统配置和网络工具文章
   - 但不会点"Hugo 技巧"，因为标签搜索更直接

3. **这个分类跟其他分类有清晰边界吗？**
   - "系统" vs "开发"：清晰（一个是系统配置，一个是开发工具）

## 💡 核心洞察

> **分类是为了"浏览"，标签是为了"搜索"**

- 用户想**随便看看** → 点分类（"我想看系统配置或站点维护"）
- 用户想**找具体内容** → 搜标签（"我想找 Hugo 相关文章"）

**记住：分类是"抽屉"，标签是"便利贴"。一个抽屉里可以有很多贴了不同便利贴的文件。**
