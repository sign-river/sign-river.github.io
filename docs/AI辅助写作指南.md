# AI 辅助写作指南

> 本文档记录了 AI 协助博主写作教程类文章的行为规范，供后续 AI 参考遵循。

## 📋 工作流程

### 第零步：选择文章模板

创建、拆分或重构文章前，必须完整阅读 [文章模板体系](文章模板.md)，并从以下三种模板中选择且只选择一种：

1. 普通单篇文章
2. 专题总分架构
3. 项目介绍文档

不得默认所有内容都使用 `index.md`，也不得自行发明第四种组织方式。选定后应复制 `templates/` 下的对应文件，再继续初始化内容。

### 第一步：初始化文章

在开始写作前，先确认以下信息：

1. **模板类型**：对应 `docs/文章模板.md` 中的三种模板之一
2. **文章分类**：对应 `docs/分类标签规范.md` 中的分类体系
3. **文章目录和文件名**：严格使用所选模板规定的结构
4. **Front Matter**：复制所选实体模板并填写完整字段

普通单篇文章的 Front Matter 示例：

```yaml
---
title: "文章标题"
date: YYYY-MM-DD
description: "一句话描述文章内容"
categories:
  - "分类"
tags:
  - "标签1"
  - "标签2"
draft: true
slug: "article-slug"
---
```

> 写作过程中保持 `draft: true`，发布前改为 `false`

---

### 第二步：协作写作

#### 基本原则

- **用户说内容，AI 负责润色**：用户用口语描述步骤，AI 整理成规范的书面表达后写入文件
- **不主动发挥**：只写用户说的内容，不擅自补充用户未提及的步骤
- **每次写完立即询问**：写完一步后说"已写入，继续说下一步"，等待用户指令

#### 专题子文章入口

- 新建专题子文章时，必须在初始化阶段同步更新同一专题的 `guide/index.md`，将文章链接放入对应的任务或问题分组。
- 子文章 Front Matter 中的 `guide` 与 `guide_title` 只提供“返回主指南”导航；它们不自动在主指南中生成入口。
- 构建前核对主指南已链接专题目录下的全部子文章；不要遗漏新建文章。

#### 图片处理规范

- **图片由用户自己粘贴**，AI 不负责插入图片
- AI 在需要插图的位置留一行**纯文字占位**，如：`欢迎界面截图`
- 占位文字**不加任何标记符号**（不用注释、不用括号）
- 用户将光标放在占位文字所在行，直接粘贴图片即可替换
- **已有的图片标签绝对不能动**，只在末尾续写新内容

#### 写入文件规范

- 每次写入前先 `Read` 确认文件当前末尾内容，避免覆盖用户已编辑的部分
- 使用 `StrReplace` 追加内容时，以文件末尾已有的内容作为 `old_string` 的锚点
- 如果 `old_string` 匹配到多处，需加入更多上下文使其唯一

---

### 第三步：完善 front matter

文章写完后检查并补全：

- `description`：根据文章内容总结一句话描述
- `tags`：补充文章中涉及的具体技术、工具名称
- `draft`：确认发布时改为 `false`

---

### 第四步：更新分类统计

文章发布后，更新 `docs/分类标签规范.md` 中的文章数量统计。

## ⚠️ 注意事项

### 关于文章分类

- 文件夹路径使用**英文**（如 `office/`、`dev/`）
- front matter 中的 `categories` 使用**中文**（如 `"办公"`、`"开发"`）
- 参考 `docs/分类标签规范.md` 保持一致

### 关于图片

- 图片存放在文章目录下的 `images/` 文件夹中
- **图片文件名命名规范**：不要中英混用，要么全用中文（如 `安装界面.png`），要么全用英文（如 `install-screen.png`）。中英混用会因自动加空格插件在中英交界处插入空格，导致路径中出现 `%20` 编码，引发图片引用与实际文件名不匹配的问题
- 图片引用格式统一为：
  ```html
  <a href="images/文件名.png" target="_blank">
    <img
      src="images/文件名.png"
      alt="image"
      style="max-width: 100%; width: 1000px;"
    />
  </a>
  ```

### 关于日期

- Hugo 将 front matter 的 date: YYYY-MM-DD 按 **UTC 零点**解析，即东八区当天 **08:00** 才生效
- 在当天 08:00 之前构建或部署时，该文章会被当作「未来文章」跳过渲染：本地 hugo server -D 看不到，CI 部署后也不出现
- 处理方式：
  - 当天写作时，日期直接写**前一天**（例如今天 08-12 写 2026-08-11），保证当天可渲染
  - 或等当天 08:00 之后发布
  - 本地强制预览可用 hugo server -D --buildFuture
- 排查方法：运行 hugo list future 查看被当作未来文章的内容

### 关于内容表达

- 操作步骤用**加粗**标注关键按钮或选项名称，如 **Next**、**I Agree**
- 命令、路径、文件名用**行内代码**格式，如 `conda --version`
- 注意事项用 blockquote（`>`）标注
- 小节标题按 `### 2.1.`、`### 2.2.` 格式编号
