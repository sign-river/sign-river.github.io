# 自定义布局相关疑问解答

## 一、为什么 `custom.scss` 添加了这么多内容？

### 原来的内容

`custom.scss` 原本只有 3 行代码，功能是隐藏页脚的 "Powered by Hugo" 字样：

```scss
.site-footer .powerby {
  display: none;
}
```

### 为什么需要新增大量样式

因为我们创建了两个**全新的页面布局**——标签页和项目页，它们的 UI 结构在 Stack 主题中是**完全不存在的**：

1. **标签页**的搜索框（`.tags-search-box`）、标签卡片（`.tag-item`）、标签云（`.tags-cloud`）等组件，都是自定义 HTML 结构，主题没有任何现成样式可以匹配它们。

2. **项目页**的卡片网格（`.projects-grid`）、项目卡片（`.project-card`）、状态徽章（`.project-status`）等，也是全新的组件。

如果不写这些样式，这些新组件会以浏览器默认的"裸样式"显示——没有背景色、没有圆角、没有间距、没有悬停效果，看上去会非常简陋且和主题风格不统一。

### 为什么不能少写？

每一段样式都有其作用：

- **布局类**（`display: flex/grid`、`gap`、`padding`）—— 控制元素的排列方式
- **外观类**（`background`、`border-radius`、`box-shadow`）—— 让组件符合 Stack 主题的视觉风格
- **交互类**（`transition`、`&:hover`、`transform`）—— 提供鼠标悬停的动效反馈
- **响应式**（`@media`）—— 确保在手机等小屏幕上也能正常显示

### 为什么用 CSS 变量（`var(--xxx)`）？

你会发现样式里大量使用了 `var(--card-background)`、`var(--accent-color)` 等写法。这些是 Stack 主题预定义的 CSS 变量，它们会随着亮色/暗色模式自动切换颜色值。使用它们可以确保自定义组件的颜色和主题保持一致，而不是写死的颜色值。

## 二、为什么标签页有单独的 `layouts/tags/` 文件夹？

这是理解这个问题的关键：**标签页和其他页面的"本质"不同**。

### Hugo 的两种页面类型

| 类型           | 说明                                               | 例子                                                            |
| -------------- | -------------------------------------------------- | --------------------------------------------------------------- |
| **普通页面**   | 你在 `content/` 下手动创建的 `.md` 文件            | 关于页、项目页、留言板、友链                                    |
| **分类法页面** | Hugo 根据文章的 tags/categories **自动生成**的页面 | `/tags/`（所有标签列表）、`/tags/Markdown/`（某个标签下的文章） |

### 其他页面为什么不需要单独文件夹

**关于页、项目页、留言板**等都是普通页面。它们的流程是：

```
content/page/about/index.md  →  主题的 single.html 模板  →  生成网页
content/page/projects/index.md  →  layouts/_default/projects.html（自定义）  →  生成网页
content/page/guestbook/index.md  →  主题的 single.html 模板  →  生成网页
```

它们用的是 `_default` 目录下的模板（通用模板），或者通过 front matter 里的 `layout: "projects"` 指定一个自定义布局名。这些模板都放在 `layouts/_default/` 下就够了。

### 标签页为什么必须有单独文件夹

`/tags/` 页面是 Hugo **自动生成**的分类法（taxonomy）页面。你不需要也不能在 `content/` 下创建一个 `/tags/` 页面来替代它（会冲突）。

Hugo 在寻找分类法页面的模板时，遵循一个**严格的查找顺序**：

```
1. layouts/tags/taxonomy.html    ← 专门给 tags 分类法的模板（最高优先级）
2. layouts/tags/list.html
3. layouts/taxonomy/taxonomy.html
4. layouts/_default/taxonomy.html
5. layouts/_default/list.html    ← 主题自带的模板（最低优先级，这也是默认用的）
```

如果我把文件命名为 `layouts/_default/taxonomy.html`，它会**同时影响**标签页和分类页。而我们只想自定义标签页的样式，不想动分类页。所以必须创建 `layouts/tags/taxonomy.html` 这个更具体的路径，让 Hugo 只对 `/tags/` 使用这个模板。

### 简单类比

可以这样理解：

- `layouts/_default/` = 通用工具箱（所有页面都能用）
- `layouts/tags/` = 标签专用工具箱（只有标签页用，且优先级更高）

如果将来你也想给分类页做自定义样式，也需要创建 `layouts/categories/taxonomy.html`。

---

## 总结

| 疑问                            | 原因                                                                                                |
| ------------------------------- | --------------------------------------------------------------------------------------------------- |
| SCSS 为什么多了这么多           | 标签云、项目卡片是全新组件，主题没有现成样式，必须从零编写                                          |
| 为什么有 `layouts/tags/` 文件夹 | `/tags/` 是 Hugo 自动生成的分类法页面，必须用特定路径覆盖模板，不能像普通页面那样放在 `_default` 下 |
