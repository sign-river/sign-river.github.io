# 文章模板体系

本站只有三种文章模板体系。新建或重构内容前，必须先从下表中选择一种；不要混用目录结构和 Front Matter。

| 模板 | 适用场景 | 内容结构 | 可复制模板 |
| --- | --- | --- | --- |
| 普通单篇文章 | 一个 `index.md` 可以完整讲清的教程、笔记或记录 | 一个 leaf bundle | `templates/standard-article/` |
| 专题总分架构 | 同一主题下至少有 3 篇可独立阅读、可独立搜索的文章 | 一篇公开主指南 + 多篇隐藏子文章 | `templates/topic-guide/` |
| 项目介绍文档 | 需要快速开始、日常使用、FAQ 等多页导航的项目 | 一个 `_index.md` + 多个有序子页面 | `templates/project-docs/` |

## 如何选择

按以下顺序判断：

1. 内容是否用于介绍和维护一个项目，并且需要项目内目录或前后翻页？是则使用“项目介绍文档”。
2. 同一主题下是否已有或计划编写至少 3 篇可独立解决问题的文章？是则使用“专题总分架构”。
3. 其他情况一律使用“普通单篇文章”。

只有 1-2 篇内容时不要提前建立专题。按顺序阅读的多章节教程通常仍是一篇普通文章；只有各部分值得拥有独立 URL 和独立搜索入口时才拆分。

## 一、普通单篇文章

复制 `templates/standard-article/index.md` 到：

```text
content/post/<分类目录>/<文章目录>/index.md
```

图片放在同级 `images/` 中。文章不设置 `type`、`layout`、`hidden`、`searchable` 或 `guide`，由 Hugo Stack 的默认文章布局渲染，并正常出现在首页、分类、归档和搜索中。

基础 Front Matter：

```yaml
---
title: "文章标题"
date: YYYY-MM-DD
description: "一句话说明文章解决的问题"
categories:
  - "分类"
tags:
  - "标签 1"
  - "标签 2"
draft: true
slug: "article-slug"
---
```

## 二、专题总分架构

专题由同一个主题目录下的两类普通 page bundle 组成，它没有专用 `type`。主指南固定放在 `guide/index.md`，不要把它写成主题目录根部的 `index.md` 或 `_index.md`：

```text
content/post/<分类目录>/<专题目录>/
├── guide/index.md
├── <子文章一>/index.md
└── <子文章二>/index.md
```

这里的 `guide/` 仍是普通 leaf bundle，所以主指南会继续作为普通文章渲染。主题目录本身只负责分组，不放置内容文件：如果使用 `index.md`，Hugo 会把整个主题目录识别为 leaf bundle；如果使用 `_index.md`，则会把它识别为 section。这两种写法都会改变当前专题架构的页面类型或子文章处理方式。

主指南是首页、分类和归档中暴露的统一入口。它按用户可识别的任务或现象分组，并链接全部子文章：

```yaml
related_group: "topic-name"
content_richness: 100
```

每篇子文章保留独立 URL 和正文，并设置：

```yaml
related_group: "topic-name"
hidden: true
searchable: true
guide: "/p/topic-guide/"
guide_title: "专题主指南名称"
```

`hidden` 使子文章不出现在首页、分类、归档和相关文章列表；`searchable` 明确保留站内搜索入口；`guide` 和 `guide_title` 在子文章标题处提供返回专题的链接。

主指南和子文章的 `related_group` 必须完全一致，主指南必须链接全部子文章。移动已有主指南时不要修改 `slug`，本站的 `/p/:slug/` 固定链接会因此保持不变。详细内容规则见 [专题汇总规范](专题汇总规范.md)。

## 三、项目介绍文档

复制整个 `templates/project-docs/` 到：

```text
content/post/projects/<项目分类>/<项目目录>/
├── _index.md
├── getting-started.md
├── daily-use.md
├── faq.md
└── images/
```

根节点必须使用 `_index.md`，所有页面必须设置 `type: "project-docs"`。根节点通过 `redirect_to` 跳转到快速开始页，子页通过 `weight` 排序，并由专属布局提供项目目录、当前页高亮以及上一页/下一页导航。

项目文档不要改用多个 `index.md` page bundle，也不要添加专题架构的 `hidden`、`searchable` 或 `guide` 字段。完整字段与可选页面见 [项目文档模板](项目文档模板.md)。

## 通用写作规则

- 写作期间保持 `draft: true`，确认发布时再改为 `false`。
- 分类和标签必须遵循 [分类标签规范](分类标签规范.md)。
- 正文标题从 `##` 开始；需要编号时按 `1.`、`1.1`、`1.1.1` 递进。
- 正文中不要使用 `---` 分隔线，`---` 仅用于 Front Matter。
- 图片放入内容目录下的 `images/`，使用相对路径引用。
- AI 协作写作还必须遵循 [AI 辅助写作指南](AI辅助写作指南.md)。

## 发布前检查

- 已明确选择三种模板中的一种，目录结构和字段与该模板一致。
- 普通文章能在列表和搜索中找到。
- 专题主指南可见，子文章从列表隐藏但可被搜索，并能返回主指南。
- 项目文档的目录、当前页高亮、跳转和前后翻页正常。
- 运行 `hugo` 完整构建且没有错误。
