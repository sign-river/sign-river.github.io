# 专题汇总规范

> 本规范是 [文章模板体系](文章模板.md) 中“专题总分架构”的详细说明。新建内容前应先通过总指南完成模板选型。

当同一产品、工具或问题域下积累了多篇独立文章时，使用“主指南 + 子文章”结构，减少首页和分类页中的重复卡片，同时保留每篇文章的站内搜索入口与独立 URL。

## 目录结构

主指南和子文章必须收纳在同一个专题目录中。主指南固定使用 `guide/index.md`：

```text
content/post/<分类目录>/<专题目录>/
├── guide/index.md
├── <子文章一>/index.md
├── <子文章二>/index.md
└── <子文章三>/index.md
```

专题目录根部不要创建 `index.md` 或 `_index.md`。前者会把专题目录变成 leaf bundle，后者会把它变成 section，均不符合本站“主指南和子文章都是独立普通页面”的架构。

## 适用条件

- 同一主题下至少有 3 篇可独立解决问题或讲解功能的文章。
- 用户通常会先寻找主题总入口，再按具体错误、功能或场景进入子文章。
- 子文章的标题、关键词和正文仍有单独搜索价值。

不适用于按顺序阅读的多章节教程、只有 1-2 篇文章的主题，或需要分别在首页长期展示的内容。

## 元数据约定

主指南保持可见，并使用统一的 `related_group`：

```yaml
related_group: "product-name"
content_richness: 100
```

每篇子文章保留原有 `slug` 和正文，并增加：

```yaml
related_group: "product-name"
hidden: true
searchable: true
guide: "/p/product-troubleshooting-guide/"
guide_title: "产品问题解决指南"
```

`hidden` 仅控制首页、分类、归档和相关文章列表；`searchable` 让子文章继续进入站内搜索索引；`guide` 会在子文章标题下显示返回主指南的链接。

## 主指南内容

主指南应按用户能识别的现象或任务分组，而不是简单按文章编号罗列。每个链接使用简洁、能区分问题的文本，并保留一个“仍未解决”小节，说明用户应提供的错误文字、路径、日志或截图。

创建专题子文章时，必须在同一次初始化中把它加入主指南的对应小节；只写子文章的 `guide` 和 `guide_title` 不能替代主指南入口。构建前应核对主指南链接与专题目录下的子文章一一对应。

分类按内容本质确定，标签保留具体产品或使用场景。例如，群星联机的 OpenVPN 搭建属于“系统”分类，`群星`、`Stellaris`、`游戏工具` 仍作为标签。

## 验收清单

- 主指南位于专题目录的 `guide/index.md`，专题目录根部没有内容文件。
- 主指南在首页和对应分类中可见。
- 子文章不出现在首页、分类、归档和相关文章列表。
- 搜索具体报错、功能或关键词仍能找到子文章。
- 子文章可返回主指南，主指南链接覆盖全部子文章。
- 运行 `hugo` 完整构建，并检查首页、搜索索引和至少一个子文章页面。
